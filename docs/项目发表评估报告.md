**当前距离**: 1-2 月补强 (P0 + P1 清单)
**难度**: 中等 (项目代码质量已高, 缺口集中在实验完整度)

## 三、项目优势

### 3.1 架构创新（强）

- **多路混合检索**: scope/typical/accepted_paper/identity_anchor 4 路并联, 后接 LTR 重排。多数已发表工作只做单路 (content-based 或 citation-based)。
- **CCF 适配（独特）**: 唯一一个直接对接 CCF 等级体系 (A/B/C + 领域分类) + 中国 CS 实际投稿场景。其他工作不做 CCF 区分, 按 venue 整体推荐。
- **LLM 角色分明的架构假设**: "LLM 当 evidence 抽取器, 不当最终裁判"。6.3 ablation 通过 3 变体对比 (direct / evidence+rule / evidence+learned) 验证这个假设。

### 3.2 方法论严谨性（强）

- **Byte-identical evidence**: 2 个 evidence 变体读同一份 snapshot, evidence bit-equal, 保证对比公平。
- **Fairness check**: 5 项独立检查 (denominator / coarse / rule / evidence_mismatches / evidence_coverage), 任何一个失败 fairness_pass=False。
- **Held-out split 已验证**: light30 (30 篇) 跟 full-v2-90 (90 篇) 完全不相交 (0 重叠), v4 LTR 在 full-v2-90 训练不会在 light30 测时有标签泄漏。
- **Baseline registry**: 4 个 baseline 正式登记 (`light30_ltr_off_v2`, `light30_ltr_on_v2`, `full_v2_90_ltr_off`, `full_v2_90_ltr_on`), 数字 bit-equal。
- **已知失败模式显式记录**: `in_llm_but_lost` 现象 (LLM 主动把 gold 排到 5 名之后) 在 6.3 ablation 中清晰可见, 驱动了"LLM 当 evidence 抽取器"的架构决定。

### 3.3 工程完整度（强）

- **FastAPI + 流式输出 + 前端 + 实时 SSE**, 可演示系统, 不是纸上系统。
- **Clean benchmark** (light30/full-v2-90) + leakage detection (`scripts/clean_benchmark.py`)。
- **accepted_paper corpus**: 102 期刊 / 208 篇真实论文, 35% CCF 期刊覆盖, LTR 的 `candidate_in_accepted_corpus` 特征强信号。
- **可解释性**: 每篇论文给 scope/typical/accepted_paper 多路证据 + LLM 6 字段 + 命中理由, 实时输出。
- **Snapshot 机制**: evidence 一次抽取, 多变体共享, 避免 8x LLM 调用重复。

### 3.6 6.4 即将贡献的理论创新（待验证）

- **26 维 LTR 真正使用 LLM evidence**: 训练和推理两端都把 6 个 evidence 字段作为内生特征, 而非外挂因子。
- **LTR score 联合公式**: `0.8×evidence + 0.2×rank` 升级为 `0.65×ev + 0.15×LTR_rank + 0.20×LTR_score`, 让 26 维 LTR 在 final score 中占实际权重。

## 四、项目劣势

### 4.1 数据集规模（小，最关键）

- **30/90 论文** vs 典型 1k-100k。logistic regression 2700 行 (90 篇), 模型基本没什么可学的。
- 训练样本 / 特征比 = 104 (90×30 / 26) → 临界, 容易过拟合。
- 验证 26 维 LTR 真实泛化能力, 需要更大数据。

### 4.2 Baseline 对比缺失

- 没跟 **SPECTER** (sentence embedding baseline) 对比
- 没跟 **Sentence-BERT** 对比
- 没跟 **BM25-only** 严格基线
- 没跟 **LearningToRank 经典库** (XGBoost/LightGBM with LambdaMART) 对比
- 没法证明 "26 维 LTR + LLM evidence" 实际比这些传统方法好

### 4.3 没有用户研究

- 纯离线评估, 没有真实研究者反馈
- 缺 5-10 个研究者的盲评 Top-5 推荐接受度
- 缺 "新研究者冷启动" 场景的用户测试

### 4.4 失败案例分析缺失

- 只报 hit@5 数字, 没分析 "在什么类型的论文上失败"
- 缺 10-20 个 hit@5=0 的论文的细粒度归因 (召回/规则/LLM 哪一步错)

### 4.5 Accepted paper 覆盖不均

- 102/295 期刊 = 35% 覆盖 (虽然已扩到 208 records, 还有 87 期刊没覆盖)
- 覆盖期刊偏向热门的 TPAMI/TOCS/TSE 等, 冷门期刊 (如 dke_2 这种边缘的) 没覆盖

### 4.6 26 维 LTR 还没验证

- 刚训练完, 还没在 full-v2-90 上跑端到端评测
- 6.4 light30 ablation 计划今天跑, 但还没跑

### 4.7 LLM 黑盒依赖

- M2.7/M3 temperature=0.2 仍有 ±5% 噪声
- LLM 抖动是结果可信度的隐忧
- 多次跑同实验可能差 1-2 篇

### 4.8 语言局限

- 只服务中文 CS, 没法推广到医学/物理等其他领域
- 英文论文也用同一 pipeline 跑, 但没专门验证迁移性

## 六、1-2 月冲刺清单 (按优先级)

### P0: 必做, 1-2 周

1. **完成 6.4 端到端验证 + 20 维回归**
   - 跑 light30 26-dim LTR + ltr_score_weight=0.3 ablation (Task 5)
   - 跑 20-dim v4 路径回归, 验证 19/30 复现 (Task 6)
   - 目标: 26-dim ≥ 19/30 (不输 20-dim), 27 维也能赢最好
2. **补 baseline 对比**
   - BM25-only: 纯 BM25 rerank, 不带任何 LLM/LTR
   - SPECTER: sentence embedding 余弦相似度排序
   - LightGBM LambdaRank: 经典 LTR 库, 26 维特征训练
   - 目标: 证明 "26 维 LTR + LLM evidence" 在 hit@5 上优于以上所有 baseline
3. **失败案例分析 (Failure Analysis)**
   - 选 10-20 个 hit@5=0 的论文, 分类失败原因
   - 召回失败 / 规则排序失败 / LLM 倒退 / LTR 学不到 / gold 不在 top-50
   - 写 1 张 "error analysis table" 进论文

### P1: 强烈建议, 2-3 周

4. **扩大测试集到 200+ 论文**
   - 从 arxiv/CCF/已有 papers_metadata_v2.jsonl 找 100-200 篇带 CCF 等级的论文
   - light30 → light200 (200 篇, 仍可控)
   - 数据集 × 3-7 倍, 模型质量显著提升
5. **重新训练 26 维 LTR 在大数据集上**
   - 200 训练论文 → 200×30 = 6000 行
   - margin 应该从 +0.2454 提升
6. **用户研究 (轻量版)**
   - 5-10 个真实研究者, 给他们 paper title+abstract, 让他们给 Top-5 推荐
   - 对比系统推荐 vs 真实研究者给的 ground truth
   - 报告 NDCG / hit@5 on human-judged

### P2: 加分, 2-4 周

7. **多语言扩展**
   - 英文论文用 SPECTER + similar pipeline, 证明架构可迁移
8. **Online 评估 (可选)**
   - 放公网跑 2 周, 收集真实流量
   - 统计用户点击行为
9. **26 维 LTR 的逐特征消融**
   - 每次去掉一个 evidence 字段 (scope_fit / method_fit / 等)
   - 量化每个证据的边际贡献
   - 给论文 "为什么 LLM evidence 有用" 提供因果证据

## 八、风险与机会

### 8.1 主要风险

1. **26 维 LTR 失败风险**: 如果 6.4 端到端 hit@5 < 19/30, 6.4 整个路线都要重做, 1-2 月计划可能延长到 3 月
2. **数据泄漏争议**: full-v2-90 训练 + full-v2-90 测虽然 88/90 没覆盖, 但 88 个交集仍可能引发审稿人质疑 (需要 held-out 5-fold 拆分)
3. **Scientometrics 审稿周期长**: 投稿到见刊可能 6-9 月
4. **同类工作被抢发**: AI 期刊推荐是热门方向, 可能有同期工作在做类似的事

### 8.2 主要机会

1. **CCF 适配是独特卖点**: 没有竞争工作做这个
2. **26 维 LTR + LLM evidence 联合公式**: 理论上有创新点
3. **方法论严谨性**: 远超同档工作, 容易在审稿中拿到方法分数
4. **代码 + 数据 + 评测一体**: 评审过程容易 track
