# 领域分类规则强化设计

> **日期**: 2026-05-28
> **目标**: 提升 area_match 准确率，重点优化人工智能、计算机网络、计算机科学理论三个领域
> **方法**: 纯 prompt 优化，在 `paper_quality_assessor_system` 中补充决策规则和边界案例

---

## 一、问题定义

当前 `paper_quality_assessor_system` 的领域分类规则存在三类误判：

| 领域 | 当前匹配率 | 误判模式 |
|------|-----------|---------|
| 人工智能 | 54.5% (6/11) | 将"ML方法研究"误判为"ML应用" |
| 计算机网络 | 60.0% (6/10) | 安全关键词触发"网络与信息安全"误判 |
| 计算机科学理论 | 66.7% (6/9) | 形式化方法被误判为软件工程 |

---

## 二、优化方案

### 补充规则一：人工智能 vs 应用领域

**核心判断准则**：论文去掉ML方法后，剩下的贡献是否为零？
- 如果是 → 标人工智能
- 如果还有领域-specific的贡献 → 归入该领域

**以下情况属于"人工智能"**，即使应用场景具体，但核心贡献在于ML方法本身：
- 提出新的特征选择算法或多视角特征融合方法 → `["人工智能"]`（特征选择是ML核心方法论）
- 提出新的模式挖掘算法（频繁模式、周期模式、异常模式等） → `["人工智能"]`。如果论文核心贡献是**算法本身**（挖掘效率、内存优化），优先标人工智能；如果核心贡献是**应用场景**（在特定领域的应用效果），则归入该领域
- 提出新的聚类算法或聚类评估指标 → `["人工智能"]`（聚类是ML基础问题）
- 对现有ML算法的收敛性、泛化界、复杂度做理论分析 → `["人工智能"]`（ML理论）

**以下情况不应标"人工智能"**，即使使用了ML技术：
- 用现有ML模型做医学图像分类，核心贡献在医学应用 → 归入具体应用领域，不加人工智能
- 用现有目标检测模型做LiDAR点云处理 → `["计算机图形学与多媒体"]`，不加人工智能
- 用户研究、可用性实验 → `["人机交互与普适计算"]`，不加人工智能

---

### 补充规则二：计算机网络 vs 网络与信息安全

**决策边界**：
- 论文的核心问题是网络性能（延迟、吞吐量、带宽分配）、网络架构、路由协议 → `["计算机网络"]`
- 论文的核心问题是安全威胁（攻击检测、入侵防御、恶意节点识别）、密码学、隐私保护 → `["网络与信息安全"]`

**边界案例**：
- "加密搜索"如果核心贡献在搜索效率/架构，属于计算机网络；如果核心贡献在加密算法安全性，属于安全
- "零信任认证"如果核心贡献在认证协议对网络性能的影响，属于计算机网络；如果核心贡献在认证算法本身的安全性，属于安全
- "GNN用于网络"如果核心问题是网络拓扑/流量预测/资源分配，属于计算机网络；如果核心问题是图神经网络本身的结构改进（如图卷积、图注意力机制），属于人工智能；如果用于异常检测且核心在检测模型，则归入相应应用领域
- 如果论文同时涉及网络性能和安全，且无法判断主次，选`["交叉/综合/新兴"]`

---

### 补充规则三：计算机科学理论 vs 软件工程

**以下情况属于"计算机科学理论"**：
- 模型检测（model checking）的形式化理论、算法复杂度分析 → `["计算机科学理论"]`
- 图论算法、组合优化、近似算法的理论分析 → `["计算机科学理论"]`
- 并行算法的复杂度分析（不涉及具体硬件实现） → `["计算机科学理论"]`
- 逻辑、形式化方法、自动机理论 → `["计算机科学理论"]`

**以下情况属于"软件工程/系统软件/程序设计语言"**：
- 程序语言设计、编译器实现、类型系统 → `["软件工程/系统软件/程序设计语言"]`
- 软件测试、验证工具的实现与评估 → `["软件工程/系统软件/程序设计语言"]`

**注意**：模型检测如果是对程序本身的验证工具实现 → 软件工程；如果是对并发系统的形式化理论分析 → 理论
